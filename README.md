# LED 屏闪烁修复台（LED Screen Flicker Restoration）

纯前端 WebGL2 + TypeScript 工具，用于修复篮球转播画面中 LED 广告屏的**亮度闪烁**与**滚动暗条纹**，同时保证屏幕外的球员、地板完全不被改动，球员横穿屏幕时也不会出错。

## 解决的问题

LED 广告屏以高刷新率（192–600 Hz）刷新，而相机以 30/60 fps 采样，两者的拍频（beat）在画面上表现为：

- 整屏亮度随时间周期性起伏（闪烁）；
- 相位沿屏幕高度逐行偏移，形成滚动暗条纹；
- 镜头摇动时屏幕在画面中移动；
- 球员会从屏幕前横穿，遮挡局部区域。

本工具在网页内完成自动检测、跟踪、参数估计与逐像素补偿，无需更换硬件。

## 四个页面

| 页面 | 功能 |
| --- | --- |
| 1. 素材 | 导入真实视频，或从 **4 快门角度 × 6 刷新率 = 24 组**合成测试矩阵中生成带真值的测试片 |
| 2. 屏幕标定 | 自动检测 LED 区域（时序闪烁打分 + 连通域 + 最大面积四边形），支持手动四点拖拽调整，回放验证镜头跟随 |
| 3. 处理预览 | A/B 对比、补偿参数调节、逐帧 GPU 计时、完整质量评估 |
| 4. 导出 | WebCodecs H.264/MP4 编码导出（无 WebCodecs 时回退 MediaRecorder/WebM） |

## 技术架构

```
视频帧
  │  texImage2D (UNPACK_FLIP_Y)
  ▼
WebGL2 下采样着色器 ──readPixels──► 低分辨率 RGB/亮度网格 (96×54)
  │                                      │
  │                                      ▼
  │                          分析层 (纯 TS，可单测)
  │                          ├─ TemporalGrid  时序环形缓冲
  │                          ├─ 屏幕检测器     闪烁能量 + 频谱一致性打分
  │                          ├─ ScreenTracker  模板 SAD + 中值全局运动（抗遮挡）
  │                          ├─ 逐行拍频估计   FFT + 加权正弦最小二乘
  │                          └─ 遮挡检测器     逐行相位预测 + 鲁棒 z/色差判定
  │                                      │
  ▼                                      ▼
WebGL2 补偿图 (每帧 3 个全屏 pass)
  ├─ 遮罩 pass：凸四边形半平面 SDF + 羽化 − 遮挡纹理
  ├─ 局部均值 pass：水平/垂直可分离盒式滤波
  └─ 复合 pass：逆增益补偿 + 对比度不退让保护，遮罩外像素原样返回
```

### 补偿模型

对屏幕内分数行 `v∈[0,1]`（顶原点），估计观测增益

```
alpha(t, v) = 1 + A · sin(2π·f·t + φ_center + slopeV·(v − 0.5))
```

着色器施加逆增益 `corrected = observed / alpha`。相位模型在屏幕中心行 `v=0.5` 处恰好还原 `φ_center`，CPU 估计器与 GLSL 共用同一公式。

### 关键正确性设计

- **逐行拟合**：滚动条纹会在整屏空间平均中自我抵消，拍频在每个网格行上独立拟合再聚合。
- **加权拟合**：被遮挡的帧权重为 0，不参与频率/相位/幅度估计。
- **凸多边形半平面判定**：不受顶点环绕方向影响，避免自交四边形导致的奇偶射线误判。
- **坐标系统一**：纹理上传翻转 Y，多边形/遮挡/条纹相位全部显式处理 GL 左下原点与图像左上原点的差异。
- **对比度保护**：局部均值随相同增益缩放，纯乘法补偿不改变相对对比度，且只放大不缩小偏差。
- **遮罩外零改动**：复合着色器在遮罩 ≤ 1/255 时直接返回原始像素，从数学上保证屏外逐位不变。

## 质量契约与实测结果

合成片（1280×720，6 Hz 拍频，含横穿球员，软件 GL 环境）端到端验收：

| 指标 | 要求 | 实测 |
| --- | --- | --- |
| 屏外改动像素比例 | ≤ 0.5% | **0.004%** |
| 广告文字对比度比 | ≥ 1.000 | **1.022** |
| 闪烁衰减 | > 0 dB | **5.6 dB** |
| 遮挡区域平均改动 | 尽量为 0 | **0.16 / 255** |
| 1080p GPU 补偿 P95 | ≤ 20 ms | **1.8 ms**（软件渲染，真实 GPU 更快） |

> 说明：20 ms 预算对应的是 GPU 逐像素补偿图（遮罩/均值/复合三个 pass）。含视频解码、CPU 分析、像素回读的整链路时间取决于素材寻址方式与硬件，不在该预算口径内。

## 开发命令

```bash
npm install
npm run dev        # 本地开发服务器
npm run build      # 类型检查 + 生产构建
npm test           # 42 个单元测试（FFT、检测、跟踪、拍频、遮挡、QA 指标、矩阵）
node scripts/e2e.mjs     # 浏览器端到端验收（需系统 Chrome）
node scripts/perf1080.mjs # 1080p GPU 帧耗时测量
```

## 已知边界

- 视频文件按固定帧率逐帧寻址（默认 30 fps）；可变帧率素材建议先转码。
- 极短快门 + 高刷新率的物理残留闪烁本身可能很弱（快门时间积分会平均掉部分高频），这是真实光学现象而非算法缺陷。
- 遮挡检测基于时序残差，对与屏幕颜色高度一致的遮挡物灵敏度有限；QA 在合成片上使用生成器真值遮罩来公正度量补偿质量。
